# BOMP 知识共享中心项目背景

更新时间：2026-10-21

本文件是项目内所有原型任务的共同业务基础。新任务开始页面设计前必须先阅读本文件；用户后续确认的新口径应同步更新到这里。

## 1. 项目定位

BOMP 知识共享中心是面向国网物资有限公司及其各部门（单位）的企业级知识管理与智能知识服务平台。

项目不是单纯的文件存储系统，而是围绕知识采集、加工、审核、共享、检索、使用、纠错、版本和归档形成闭环，并将知识能力嵌入 BOMP 采购管理、成本事项管理等业务场景。

平台同时是公司统一的非结构化知识数据管理载体，承载各部门在管理和业务工作中形成或使用的制度规范、模板工具、方案案例、报告汇报、培训宣贯、多媒体素材、风险合规等知识文件。建设遵循“构建知识目录、夯实知识底座、基础智能先行、深化智能应用”的总体思路，围绕知识归集与规范管理、能力沉淀及传承、赋能智慧办公应用三个目标分阶段推进。

## 2. 建设目标

- 统一管理公司知识、部门知识、个人知识、协作知识及临时共享文件。
- 建立公司级、部门级、多级目录、分类标签和元数据体系。
- 完成上传、查重、命名检查、智能标引、人工确认、审核和发布流程。
- 通过角色、组织、岗位和文件动作实现精细化权限控制。
- 提供关键词、正文、组合条件、语义和多模态检索。
- 检索结果支持对单个知识文件发起 AI 速读；速读内容作为按需上下文侧栏展示，不在未选择文件时占用结果区空间。AI 问答、知识检索和图片检索保留可展开、可收起的统一历史记录入口。
- 提供智能问答、材料起草、文稿优化、知识速读和智能总结能力。
- 智能问答支持用户携带文件或图片提问；回答引用必须可追溯到具体相关文件。检索到的受限知识只展示最小必要元数据和访问权限申请入口，不向无权用户泄露正文或附件内容。
- 保留授权、审核、版本、纠错、下架和文件操作记录，实现可追溯、可审计。

### 分阶段建设目标

- 第一阶段“夯基础、通链路”：建设目录、标签、知识底座和基础智能能力，贯通知识沉淀、流转与应用链路，计划于 2027 年 1 月底前完成。
- 第二阶段“拓场景、智协同”：持续扩展智能总结、知识聚合、本地文档整理及专业智能应用，并推进非结构化知识与结构化经营数据协同。

## 3. 核心业务链路

```text
本地文件或业务资料
  -> 批量上传、查重和命名检查
  -> 元数据提取、智能标引和多模态加工
  -> 人工确认
  -> 共享提报与分级审核
  -> 个人、部门或公司知识库发布
  -> 检索、问答、协作、材料起草和智能总结
  -> 纠错、版本、下架、更新和持续沉淀
```

待审知识在全部适用审核环节通过前不得正式发布，也不得向普通访问者展示正文或附件。

智能标引至少包括解析文件名、标签属性和文件内容，推荐专业标签与知识类型标签，并提取文档摘要、关键词等辅助信息。系统推荐结果必须由上传人核对，可修改或补充后再确认。

## 4. 角色定义

| 角色编号 | 角色 | 主要职责 |
|---|---|---|
| `R_BOMP_01` | 员工 | 管理个人知识，访问授权知识，发起共享、权限申请或备案相关业务 |
| `R_BOMP_02` | 部门知识库管理员 | 上传和管理本部门知识，维护部门目录、成员、可见范围和权限，并可将部门知识提报至公司知识库 |
| `R_BOMP_03` | 部门知识库审核人 | 审核员工共享至部门知识库和公司知识库的申请，并处理部门存量知识入库审核 |
| `R_BOMP_04` | 专业管理部门知识库审核人 | 处理公司级知识专业审核 |
| `R_BOMP_05` | 法律事务部合规审查人 | 处理公司级知识法律合规审查 |
| `R_BOMP_06` | 综合管理部保密审查人 | 处理公司级知识保密审查 |
| `R_BOMP_07` | 公司知识库管理员 | 管理公司知识中心、公司目录、知识文件和访问范围 |
| `R_BOMP_08` | 知识共享中心运营管理员 | 维护共享中心功能、权限配置和运营工作 |
| `R_BOMP_09` | 工作规则编制部门用户 | 提交工作规则新增、更新或废止备案 |
| `R_BOMP_10` | 总法律顾问审核人 | 处理工作规则备案终审 |

### 已确认角色口径

部门知识库管理员和部门知识库审核人是两个独立角色：

- 部门知识库管理员负责目录、知识文件、成员、统计、可见范围和授权管理。
- 部门知识库审核人负责审核任务处理，不因拥有审核角色而自动获得知识库管理权限。
- 两类角色的导航入口、工作台、按钮权限和服务端权限含义必须独立表达，不得在原型中合并。
- 部门知识库管理员的上传入口属于部门知识库管理域，不复用员工“我的上传”作为主入口；两者可共享上传、处理和标引确认组件，但目标库、可选目录、默认权限及后续流转不同。
- 部门知识库管理工作台覆盖知识统计、知识管理、上传任务、共享提报、回收站和管理日志，作为部门知识库管理员的统一操作入口，不提供目录管理页签；公司知识库专业目录管理页面保留兼容地址但不作为公共侧边导航子项。
- 部门知识统计首页使用部门知识总量、本月新增和 AI 引用次数三项概览；供应链运营中心全部 14 个一级目录知识量在一屏窄条形图中比较，知识使用趋势以访问、下载、收藏和 AI 引用四条折线展示。
- 公司知识库专业目录管理用于维护公司级专业分类体系和归入该体系的知识，包含统计、知识、目录、回收站和管理日志；公司知识库管理用于维护公司公开知识资产，包含统计、知识、部门目录、上传任务、共享、回收站和管理日志，并由公司知识库管理员发起公司知识上传。两者的统计分布和使用趋势均按上下全宽布局展示，并保留各自统计口径和数据。
- 当前专业目录管理的目录树与公共侧栏“部门知识库”共用 `知识目录/部门级、公司级文件共享层级示例_供应链运营中心 .xlsx` 的“部门知识库样例”。根节点为“供应链运营中心”，B-E 列形成 14 个一级目录及其完整下级文件夹，F 列知识文件不作为目录节点。专业目录管理页默认展开全部有子级节点，公共侧栏仅展开当前选中路径。
- 公共侧栏“公司知识库”与“公司知识库管理 > 目录管理”共用 `知识目录/公司级.xlsx` 的“公司知识库目录层级”，按 B-G 列完整展示 11 个一级目录及其后全部文件夹层级，H 列知识资料内容不作为目录节点；目录管理是两处展示的唯一数据口径。

## 5. 权限原则

- 公司级知识默认全员可见，但可限定指定部门或岗位人员。
- 部门级知识默认本部门可见，可向指定部门或人员定向共享。
- 普通员工在公共“部门知识库”和“公司知识库”中仅浏览和使用已授权目录与文件，不具备新建文件夹的权限；目录维护属于对应的部门或公司知识库管理域。
- 个人级知识默认仅创建人可见，可定向授予查看、编辑或管理权限。
- 权限动作至少包括审批、上传、查看、下载、删除、收藏、分享和管理。
- 页面入口、按钮显示和实际操作权限必须保持一致，不能只通过隐藏菜单模拟权限控制。
- 无权用户不得获得受限正文、附件或预览；允许发现时只能展示最小必要元数据并提供权限申请入口。
- 授权范围、有效期、权限继承、权限收回和关键操作必须可追溯。

## 6. 审核流程

- 个人知识共享至部门知识库：员工提交，部门知识库审核人审核。
- 个人知识共享至公司知识库：部门初审、专业审核、法律合规审查、保密审查后发布。
- 部门知识共享至公司知识库：从专业审核开始，不重复执行个人来源的部门初审。
- 公司知识库管理员直接提报公司知识：进入专业、合规和保密审核链。
- 审核支持通过、退回、填写意见、修改后重新提交，并完整保存处理轨迹。
- 工作规则备案依次流转至综合管理部、法律事务部和总法律顾问。
- “审核工作台”统一汇总待审核、已通过和已退回申请，支持按状态、提交日期、关键词或提交人筛选，并支持待审核任务的单条和批量处理；申请详情展示知识基本信息、AI 速读、目标入库目录和审核操作。审核工作台作为个人中心下方的独立一级导航入口。

### 部门知识库管理员上传知识的当前执行口径

实施方案正文写明部门知识库管理员可直接上传部门知识，附件流程图则将“上传部门级存量归档知识”流转至部门知识库审核人，两处对是否需要部门审核的表达不完全一致。为避免未审知识直接发布，当前原型按以下保守口径执行：

1. 部门知识库管理员从“知识库管理 > 部门知识库管理 > 知识管理”进入“上传知识”。
2. 上传目标固定为当前管理员所属部门的部门知识库，管理员选择目标目录，可一次添加多个文件。
3. 系统依次完成上传、格式检查、重复文件校验、命名检查、内容解析和智能标引，并逐文件展示进度与异常原因。
4. 管理员核对并补充文件名称、所属目录、专业标签、知识类型、版本、关键词、摘要、有效期和可见范围；层级标签固定为“部门级”。
5. 确认后提交部门知识库审核人，状态变为“待部门审核”；审核通过后发布至部门知识库，退回后由管理员修改并重新提交。
6. 共享至公司知识库是部门知识正式入库后的独立动作，不与首次上传合并；提报后从专业管理部门审核开始，再进入合规与保密审查。

若后续明确部门知识库管理员上传可免部门审核，只需将第 5 步的提交结果调整为“已发布”，其余上传、智能处理和标引确认页面结构保持不变。

## 7. 功能范围

需求说明书确定的核心功能域包括：

- 共享中心首页
- 文件分级分类管理
- 公司知识中心
- 部门知识库
- 文件权限管理
- 知识审核管理
- 知识检索
- 临时共享网盘
- 多层级文件夹管理
- 个人中心
- 工作规则备案
- 重复文件校验
- 群组文件管理

最小功能单元表进一步覆盖 21 个二级业务模块、61 条三级功能记录，重点扩展：

- 标签全生命周期和标签目录映射
- 统一元数据模型
- 多模态知识加工和向量质量校验
- 个人知识库、知识协作和定向分享
- 在线协同编纂与版本管理
- 全局智能问答和跨模态检索
- 材料智能起草与文稿优化
- 嵌入业务页面的智能办公助手
- 会议纪要、合同条款和项目报告智能总结
- 本地文档扫描、整理、备份回滚和云端同步

实施方案进一步明确知识标签至少覆盖层级、专业、知识类型、版本、关键词，并可扩展主题词、文档摘要、有效期等基础信息。各部门提出专业标签更新需求时，需先完成部门内部审核，再提报综合管理部审核确认。

标签管理页面按层级、专业、知识类型和版本维护标签定义及选择方式。新增标签不直接生效，统一提交系统管理员审批；标签停用不移除已有知识的标引，删除仅在没有任何知识文件关联时允许，并在删除前进行二次确认。

## 8. 系统规模与演示边界

- 规划注册用户约 400 人，最大在线用户约 50 人。
- 业务正常时约 5 笔/分钟，高峰时最大约 10 笔/分钟。
- 首页、登录、页面打开和基本提交正常时平均响应要求小于 3 秒。
- 当前交付为客户演示用 HTML 原型，不实现真实接口、复杂校验、真实权限系统和数据持久化。
- 原型必须通过页面入口、状态、按钮和可点击链路准确表达业务和权限差异。
- 部门知识库统计看板以“供应链运营中心”为当前部门上下文，知识分布使用该部门全部一级目录；引用、下载、收藏和 AI 引用次数作为可独立排序的知识使用指标。
- 个人中心作为员工个人工作入口，集中提供个人信息、浏览记录、下载记录、上传任务、共享提报进度、待办审核和回收站；“我的共享”用于查看本人发起的共享及审核进度，“我的审批”用于处理当前用户负责的审核任务。个人上传与审批处理属于员工个人域，不与部门知识库管理员的管理上传入口合并。浏览记录和下载记录支持选择后批量删除；下载记录中的文件目录可作为回到知识库目录的入口。
- “我的知识库 > 最近使用”支持勾选一条或多条知识后批量发起共享提报，也支持从单条文件的“更多”菜单直接提报；未选择记录时批量入口不可用。两类入口进入同一共享提报弹窗，由员工选择部门或公司知识库、一个或多个目标目录、可见范围并可填写共享说明；多目录通过“增加目录”逐条添加，每一条均可从公共知识目录的任意层级选择。目标目录与公共侧边导航使用同一份部门级或公司级完整目录数据，确认后进入对应共享审核演示反馈，不与直接分享操作混淆。
- 知识共享中心首页承担 AI问答和文件检索入口，不展示结构化高级搜索。AI问答支持自然语言输入、附件和图片；搜知识使用独立单行文件搜索框，仅按知识库范围和文件名称、关键词或正文内容发起检索，不支持附件或图片。“搜知识”结果页提供高级搜索，用于按上传日期、上传部门、上传人、类型与公开范围等元数据组合定位文档，所有条件同时满足后才进入结果集，适用于目标明确的定向检索。

## 9. 原型共同约束

- 页面视觉与交互遵循 `docs/prototype-guidelines.md`。
- 公共结构优先复用 `components` 中已登记组件。
- 页面使用组件后更新 `components/registry.json` 的 `usedBy`。
- 示例数据使用国网物资知识库业务语境，不使用无意义占位内容。
