# BOMP 原型项目 Codex 接手说明

更新时间：2026-10-27

## 1. 接手目标

本项目是 BOMP 知识共享中心桌面端 HTML 原型。后续工作应在现有页面、公共组件、目录数据和视觉规范上继续迭代，不要另起一套框架或复制公共组件。

技术栈固定为纯 HTML、CSS 和原生 JavaScript，不需要安装前端框架。

## 2. 开始前必读

按以下顺序阅读：

1. `AGENTS.md`
2. `docs/project-background.md`
3. `docs/prototype-guidelines.md`
4. `components/README.md`
5. `components/registry.json`
6. `docs/decision-log.md`

用户后续明确批注高于历史规则；确认新口径后同步更新规则和决策记录。

## 3. 本地启动

在项目根目录执行：

```powershell
.\scripts\start-prototype-server.ps1
```

该脚本会先加载 `scripts/use-local-env.ps1`，将临时文件和工具缓存限制在项目目录内，再优先使用 Node.js 内置模块启动静态服务器；未安装 Node.js 时会尝试 Python 3。无需安装 npm 依赖。若 PowerShell 执行策略阻止脚本，可在当前终端使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-prototype-server.ps1
```

首页：

```text
http://127.0.0.1:4173/pages/prototype-suite/home.html
```

如果 4173 端口已占用，可换用其他本地端口。不要将服务绑定到公网地址。

```powershell
.\scripts\start-prototype-server.ps1 -Port 4174
```

## 4. 在另一台电脑的 Codex 中接手

1. 将交接 ZIP 解压到本机可写目录，目录路径尽量不要包含过长层级。
2. 在 Codex 中把解压后的项目根目录作为工作区打开，不要只打开某个 HTML 文件。
3. 首次对话先要求 Codex 按第 2 节顺序读取项目资料，再描述新的修改需求。
4. 在 Codex 终端运行 `scripts/start-prototype-server.ps1`，通过本地 URL 查看原型。
5. 每轮修改后执行第 10 节的校验命令，并按 `AGENTS.md` 同步规则与决策记录。

本快照没有 Git 仓库，也不包含历史提交。建议接手者解压后立即初始化自己的版本管理；在此之前请保留原始 ZIP，作为可恢复基线。

## 5. 核心目录

- `pages/prototype-suite/`：当前原型套件页面、页面样式和交互逻辑。
- `pages/prototype-suite/suite.js`：大部分页面渲染、演示数据和交互入口。
- `pages/prototype-suite/suite.css`：原型套件页面样式。
- `components/`：顶部栏、侧边栏、知识表格、文件操作弹窗、历史记录面板等公共组件。
- 顶部栏右侧全局按“你好，用户名、退出图标”排列；部门和公司知识库管理页面及部门上传知识流程的用户名为“管理员”。
- `components/registry.json`：组件版本和 `usedBy` 页面登记。
- `知识目录/`：部门级和公司级真实目录数据源。
- `scripts/verify-prototype-suite.js`：原型结构和关键规则回归校验。
- `scripts/start-prototype-server.ps1`、`scripts/serve-prototype.js`：本地静态服务器启动入口及其零依赖 Node.js 实现。
- `scripts/visual-qa-*.js`：专项视觉检查脚本，部分脚本依赖本机 Playwright 运行时。
- `.agents/skills/`：本项目决策记录引用的本地设计技能资料，随交接包保留；是否被新环境自动发现取决于接手者的 Codex 配置，不影响原型运行。

## 9. 修改规则

- 通用 UI 优先修改 `components/`，并同步所有 `usedBy` 页面和组件登记。
- 页面专属样式必须使用页面或业务作用域，避免污染其他页面。
- 设计基准为 1440px，至少检查 1280px，不得产生横向滚动。
- 名称列优先自动吸收空间，其他列按内容长度分配比例；名称和其他字段全部保持单行，空间不足时省略并保留完整提示。
- 全系统业务表格有复选框时以“复选框、名称”起始，无复选框时名称为首列，操作固定为末列；中间字段使用一致的 12px 左右内边距，操作列表头、单元格和按钮组统一右对齐并距表格右端保留 28px。
- 删除、下架等危险操作使用确认交互；成功提示 2 秒自动消失。
- 所有项目缓存、临时文件、截图和产物保存在项目目录内，运行生成文件的命令前先加载 `scripts/use-local-env.ps1`。
- 原型没有后端数据库。页面中新建文件夹、重命名、删除、筛选和选择等演示操作主要保存在当前页面内存中，刷新页面后恢复到源码中的初始数据；少量搜索条件和侧栏宽度使用 `sessionStorage`，浏览器会话结束后失效。

## 10. 每轮校验

至少执行：

```powershell
node --check pages/prototype-suite/suite.js
node scripts/verify-prototype-suite.js
node -e "JSON.parse(require('fs').readFileSync('components/registry.json','utf8')); console.log('components/registry.json valid')"
```

页面改动后还应在 1440px 和 1280px 视口检查：

- 页面无横向滚动。
- 文本和操作不重叠、不截断关键内容。
- 导航高亮、筛选、状态切换、弹窗和列表操作可点击。
- 修改范围之外的页面没有被公共样式误伤。

本交接快照已于 2026-10-28 通过以上三项校验。原型套件公共脚本与样式为 `2.36.0`，公共基础样式为 `2.3.0`，知识表格组件为 `1.4.0`，侧边栏组件为 `4.5.1`，顶部栏组件为 `4.2.0`。
