# BOMP 知识共享中心项目背景

更新时间：2026-09-03

本文件是项目内所有原型任务的共同业务基础。新任务开始页面设计前必须先阅读本文件；用户后续确认的新口径应同步更新到这里。

## 1. 项目定位

BOMP 知识共享中心是面向国网物资有限公司及其各部门（单位）的企业级知识管理与智能知识服务平台。

项目不是单纯的文件存储系统，而是围绕知识采集、加工、审核、共享、检索、使用、纠错、版本和归档形成闭环，并将知识能力嵌入 BOMP 采购管理、成本事项管理等业务场景。

## 2. 建设目标

- 统一管理公司知识、部门知识、个人知识、协作知识及临时共享文件。
- 建立公司级、部门级、多级目录、分类标签和元数据体系。
- 完成上传、查重、命名检查、智能标引、人工确认、审核和发布流程。
- 通过角色、组织、岗位和文件动作实现精细化权限控制。
- 提供关键词、正文、组合条件、语义和多模态检索。
- 提供智能问答、材料起草、文稿优化、知识速读和智能总结能力。
- 保留授权、审核、版本、纠错、下架和文件操作记录，实现可追溯、可审计。

## 3. 核心业务链路

```text
本地文件或业务资料
  -> 批量上传、查重和命名检查
  -> 元数据提取、智能标引和多模态加工
  -> 人工确认
  -> 共享提报与分级审核
  -> 个人、部门或公司知识库发布
  -> 检索、问答、协作、材料起草和智能总结
  -> 纠错、版本、下架、更新和持续沉淀
```

待审知识在全部适用审核环节通过前不得正式发布，也不得向普通访问者展示正文或附件。

## 4. 角色定义

| 角色编号 | 角色 | 主要职责 |
|---|---|---|
| `R_BOMP_01` | 员工 | 管理个人知识，访问授权知识，发起共享、权限申请或备案相关业务 |
| `R_BOMP_02` | 部门知识库管理员 | 管理本部门知识、目录、成员、可见范围和权限 |
| `R_BOMP_03` | 部门知识库审核人 | 处理部门级共享审核及本部门公司级共享初审 |
| `R_BOMP_04` | 专业管理部门知识库审核人 | 处理公司级知识专业审核 |
| `R_BOMP_05` | 法律事务部合规审查人 | 处理公司级知识法律合规审查 |
| `R_BOMP_06` | 综合管理部保密审查人 | 处理公司级知识保密审查 |
| `R_BOMP_07` | 公司知识库管理员 | 管理公司知识中心、公司目录、知识文件和访问范围 |
| `R_BOMP_08` | 知识共享中心运营管理员 | 维护共享中心功能、权限配置和运营工作 |
| `R_BOMP_09` | 工作规则编制部门用户 | 提交工作规则新增、更新或废止备案 |
| `R_BOMP_10` | 总法律顾问审核人 | 处理工作规则备案终审 |

### 已确认角色口径

部门知识库管理员和部门知识库审核人是两个独立角色：

- 部门知识库管理员负责目录、知识文件、成员、统计、可见范围和授权管理。
- 部门知识库审核人负责审核任务处理，不因拥有审核角色而自动获得知识库管理权限。
- 两类角色的导航入口、工作台、按钮权限和服务端权限含义必须独立表达，不得在原型中合并。

## 5. 权限原则

- 公司级知识默认全员可见，但可限定指定部门或岗位人员。
- 部门级知识默认本部门可见，可向指定部门或人员定向共享。
- 个人级知识默认仅创建人可见，可定向授予查看、编辑或管理权限。
- 权限动作至少包括审批、上传、查看、下载、删除、收藏、分享和管理。
- 页面入口、按钮显示和实际操作权限必须保持一致，不能只通过隐藏菜单模拟权限控制。
- 无权用户不得获得受限正文、附件或预览；允许发现时只能展示最小必要元数据并提供权限申请入口。
- 授权范围、有效期、权限继承、权限收回和关键操作必须可追溯。

## 6. 审核流程

- 个人知识共享至部门知识库：员工提交，部门知识库审核人审核。
- 个人知识共享至公司知识库：部门初审、专业审核、法律合规审查、保密审查后发布。
- 部门知识共享至公司知识库：从专业审核开始，不重复执行个人来源的部门初审。
- 公司知识库管理员直接提报公司知识：进入专业、合规和保密审核链。
- 审核支持通过、退回、填写意见、修改后重新提交，并完整保存处理轨迹。
- 工作规则备案依次流转至综合管理部、法律事务部和总法律顾问。

## 7. 功能范围

需求说明书确定的核心功能域包括：

- 共享中心首页
- 文件分级分类管理
- 公司知识中心
- 部门知识库
- 文件权限管理
- 知识审核管理
- 知识检索
- 临时共享网盘
- 多层级文件夹管理
- 个人中心
- 工作规则备案
- 重复文件校验
- 群组文件管理

最小功能单元表进一步覆盖 21 个二级业务模块、61 条三级功能记录，重点扩展：

- 标签全生命周期和标签目录映射
- 统一元数据模型
- 多模态知识加工和向量质量校验
- 个人知识库、知识协作和定向分享
- 在线协同编纂与版本管理
- 全局智能问答和跨模态检索
- 材料智能起草与文稿优化
- 嵌入业务页面的智能办公助手
- 会议纪要、合同条款和项目报告智能总结
- 本地文档扫描、整理、备份回滚和云端同步

## 8. 系统规模与演示边界

- 规划注册用户约 400 人，最大在线用户约 50 人。
- 业务正常时约 5 笔/分钟，高峰时最大约 10 笔/分钟。
- 首页、登录、页面打开和基本提交正常时平均响应要求小于 3 秒。
- 当前交付为客户演示用 HTML 原型，不实现真实接口、复杂校验、真实权限系统和数据持久化。
- 原型必须通过页面入口、状态、按钮和可点击链路准确表达业务和权限差异。

## 9. 原型共同约束

- 页面视觉与交互遵循 `docs/prototype-guidelines.md`。
- 公共结构优先复用 `components` 中已登记组件。
- 页面使用组件后更新 `components/registry.json` 的 `usedBy`。
- 示例数据使用国网物资知识库业务语境，不使用无意义占位内容。
